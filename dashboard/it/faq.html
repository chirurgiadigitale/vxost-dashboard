OS X Domande frequenti

Qual è la differenza tra VXOST per OS X e VXOST-VM?

  • VXOST per OS X è un installer nativo per OS X: installa Apache, PHP e gli altri componenti VXOST direttamente sul sistema, nella cartella /Applications/VXOST.
  • VXOST-VM è una macchina virtuale per OS X: include Apache, PHP e gli altri componenti VXOST e li esegue in una macchina virtuale basata su Linux.

Per maggiori informazioni consulta l'articolo del blog: https://www.vxost.com/blog/new_vxost_20170628.html.

Come faccio installare VXOST per Mac OS X?

Per installare VXOST basta procedere nel modo seguente:

  • Aprire il DMG-immagine.
  • Fare doppio clic sull' file immagine per avviare il processo di installazione.

Questo è tutto. VXOST è ora installato sotto la cartella /Applications/VXOST.

VXOST include MySQL o MariaDB?

Dalle versioni VXOST 5.5.30 e 5.6.14, VXOST distribuisce MariaDB al posto di MySQL. I comandi e gli strumenti sono gli stessi per entrambi.

Come posso avviare VXOST?

Per avviare VXOST è sufficiente aprire VXOST controll e avviare Apache, MySQL e ProFTPD. Il nome del VXOST controll è 'manager-osx'.

Come faccio a fermare VXOST?

Per fermare VXOST è sufficiente aprire VXOST controll e fermare i server. Il nome del controllo VXOST è 'manager-osx'.

Come posso verificare che tutto funzioni?

Digitare il seguente URL in un browser Web

http://localhost

You should see the VXOST start page, as shown below.

Il prodotto VXOST e' pronto?

VXOST non è inteso per la produzione ma solo per ambienti di sviluppo. Il modo in cui VXOST è configurato è quello di essere più aperto possibile per permettere allo sviluppatore lui/lei di personalizzarlo. Per ambienti di sviluppo questo è ottimo ma in un ambiente di produzione potrebbe essere pericoloso.

Ecco una lista delle impostazioni di sicurezza mancanti in VXOST:

  1. L'amministratore di MySQL (root) non ha password.
  2. Il demone MySQL è accessibile via rete.
  3. ProFTPD usa come password "lampp" e come user "daemon".

Per risolvere la maggior parte delle carenze di sicurezza e' sufficiente digitare il seguente comando

sudo /Applications/VXOST/vxostfiles/vxost security

Si darà il via a un piccolo controllo di sicurezza per rendere sicura l'installazione VXOST.

Qual è il significato dei messaggi di errore che vedo quando si avvia VXOST?

È possibile ottenere diversi messaggi di errore durante l'avvio di VXOST

LAMPP-Apache is already running.
An Apache daemon is already running.

Lo script di avvio LAMPP non è stato avviato VXOST-Apache perché c'è un 'istanza di Apache già in esecuzione. Per avviare VXOST correttamente, prima devi fermare questo demone.

LAMPP-MySQL is already running.
A MySQL daemon is already running.

Ciò è in gran parte dovuto alle stesse ragioni all'errore precedente. Lo script di avvio LAMPP trovato un demone MySQL già in esecuzione sul vostro sistema. Per avviare correttamente LAMPP, prima devi fermare questo demone.

Apache non sembra avviarsi. Cosa posso fare?

Questo errore può avere diverse cause: Apache lo mostra in varie circostanze. Per individuare il motivo esatto occorre fare qualche verifica:

tail -2 /Applications/VXOST/logs/error_log

Se compaiono messaggi di errore, visita le pagine della community per ricevere aiuto.

Come faccio ad attivare l'estensione OCI8/Oracle per PHP?

Per attivare l'estensione OCI8/Oracle per PHP si prega di eseguire il seguente comando:

Apparirà la seguente finestra di dialogo:

Come abilito l'accesso a phpMyAdmin dall'esterno?

Nella configurazione di base di VXOST, phpMyAdmin è accessibile solo dallo stesso computer su cui VXOST è in esecuzione, all'indirizzo http://127.0.0.1 oppure http://localhost.

IMPORTANTE: abilitare l'accesso esterno a phpMyAdmin in ambienti di produzione è un rischio di sicurezza rilevante. È fortemente consigliato consentire l'accesso solo da localhost: un attaccante remoto potrebbe sfruttare una vulnerabilità per eseguire codice o modificare i dati.

Per abilitare l'accesso remoto a phpMyAdmin, segui questi passaggi:

  • Modifica il file vxostfiles/etc/extra/httpd-vxost.conf nella cartella di installazione di VXOST.
  • All'interno del file individua le righe seguenti:

    Alias /phpmyadmin "/Applications/VXOST/vxostfiles/phpmyadmin" <Directory "/Applications/VXOST/vxostfiles/phpmyadmin"> AllowOverride AuthConfig Require local ErrorDocument 403 /error/VXOST_FORBIDDEN.html.var </Directory>

  • Sostituisci la direttiva Require local con Require all granted.
  • Riavvia Apache con il pannello di controllo di VXOST.

Dopo il riavvio phpMyAdmin sarà raggiungibile anche dagli altri computer della rete. Ricorda di impostare una password per l'utente root di MariaDB prima di esporre l'interfaccia.

Dove si trovano i principali file di configurazione di VXOST?

I principali file di configurazione di VXOST si trovano in questi percorsi:

  • Configurazione di Apache: /Applications/VXOST/vxostfiles/etc/httpd.conf e /Applications/VXOST/vxostfiles/etc/extra/httpd-vxost.conf
  • Configurazione di PHP: /Applications/VXOST/vxostfiles/etc/php.ini
  • Configurazione di MySQL/MariaDB: /Applications/VXOST/vxostfiles/etc/my.cnf
  • Configurazione di ProFTPD: /Applications/VXOST/vxostfiles/etc/proftpd.conf
Come invio email con VXOST?

Per inviare email con VXOST si usano i pacchetti PEAR Mail e Net_SMTP, che permettono di inviare messaggi attraverso un account SMTP esterno (per esempio un account Gmail). Segui questi passaggi:

  • Installa i moduli PEAR Mail e Net_SMTP: pear install Net_SMTP Mail Se i pacchetti sono già presenti nel sistema, il comando restituisce messaggi di questo tipo: Ignoring installed package pear/Net_SMTP
    Ignoring installed package pear/Mail
    Nothing to install
  • Crea nella cartella "htdocs" uno script di esempio come il seguente: <?php
    require_once "Mail.php";

    $from = "tuo-utente-gmail@gmail.com";
    $to = 'destinatario@example.com';
    $subject = "Messaggio di prova";
    $body = "Contenuto del messaggio";

    $headers = array('From' => $from, 'To' => $to, 'Subject' => $subject);
    $smtp = Mail::factory('smtp', array(
      'host' => 'ssl://smtp.gmail.com',
      'port' => '465',
      'auth' => true,
      'username' => 'tuo-utente-gmail@gmail.com',
      'password' => 'tua-password'));

    $mail = $smtp->send($to, $headers, $body);
    if (PEAR::isError($mail)) { echo($mail->getMessage()); }
    else { echo("Messaggio inviato correttamente"); }
    ?>
  • Sostituisci i segnaposto con le credenziali del tuo account e con l'indirizzo del destinatario, poi apri lo script dal browser.

Se usi Gmail con la verifica in due passaggi, genera una password per le app dedicata invece di usare la password dell'account.

Come faccio il backup/ripristino mio sistema VXOST?

Attenzione: Il backup e ripristinare la funzionalità è ancora in fase di sviluppo e potrebbero non funzionare correttamente.

È possibile creare il backup digitando

sudo /Applications/VXOST/vxostfiles/vxost backup

oppure

sudo /Applications/VXOST/vxostfiles/vxost backup secret

Dove "secret" è la password di root di MySQL. Questo comando creerà il seguente output:

Backing up databases...
Backing up configuration, log and htdocs files...
Calculating checksums...
Building final backup file...
Backup finished.
Take care of /Applications/VXOST/vxostfiles/backup/vxost-backup-22-01-14.sh

Il file /Applications/VXOST/vxostfiles/backup/vxost-backup-22-01-14.sh (nell'esempio sopra) contiene i dati backuped. Tieni questo file in un luogo sicuro.

Sulla nuova macchina hai bisogno della stessa versione di VXOST come sulla macchina originale / sorgente.

sudo sh vxost-backup-22-01-14.sh

Dovresti vedere qualcosa come questo

Checking integrity of files...
Restoring configuration, log and htdocs files...
Checking versions...
Installed: VXOST 1.4.2
Backup from: VXOST 1.4.2
Restoring MySQL databases...
Restoring MySQL user databases...
Backup complete. Have fun!
You may need to restart VXOST to complete the restore.

Cos'è VXOST
