A complete restyling of the XAMPP web root: dashboard, documentation and three
new tools, all sharing one dark design system built around the official XAMPP
orange.

No design framework, no CSS or JavaScript dependency, no external request while
you use it. Icons are inline SVG or CSS masks.

 2. WHAT CHANGED
-------------------------------------------------------------------------------

INTERFACE
  - Dark theme by default, light theme included, switched from the navigation
    bar and remembered by the browser.
  - Palette built on the official XAMPP orange #FB7A24, read from the logo
    artwork. Every colour pair was checked against WCAG contrast ratios.
  - Inter typeface, falling back to system fonts when unavailable.
  - Full width navigation bar, always visible at the top, identical on every
    page: Dashboard, Projects, Database, Ports & IPs, PHPInfo, FAQs, HOW-TO
    Guides.
  - Full width footer on five columns, present everywhere.
  - Mobile-first layout checked at 375, 768, 1024 and 1440 pixels.

CONTENT
  - Homepage rebuilt: live service status, quick access, stack summary and the
    development-only warning.
  - HOW-TO guides turned into a grid of cards with an icon per topic.
  - 404 page redesigned and, at last, actually served by Apache.
  - phpinfo() output split into collapsible sections with a table of contents
    and a filter.

 3. NEW PAGES
-------------------------------------------------------------------------------

PROJECTS                          http://localhost/progetti/
  Lists the folders under htdocs/progetti and detects the technology behind
  each one (WordPress, Laravel, Node, Next/Nuxt, Composer, PHP, HTML), looking
  one level deeper as well, since many folders are containers.
  Instant search, filters by technology, grid or list view, alphabetical order,
  last modification date, and a direct link to the VirtualHost port when one
  exists.
  On a fresh install the folder is empty and the page explains that.

PORTS & IPS                       http://localhost/dashboard/ports.php
  Lists the listening TCP ports, the process holding each one and the project
  it belongs to, resolved from the VirtualHost configuration or from the
  process working directory.
  Shows the addresses of the machine, explains the difference between localhost
  and 127.0.0.1, lists the virtual hosts including the disabled ones, shows the
  projects that have no dedicated port, and documents how to open a new one.

DATABASE                          http://localhost/dashboard/database.php
  phpMyAdmin framed by the dashboard, with the navigation bar and the footer
  always visible. phpMyAdmin stays the original application, so it keeps
  updating normally. See section 12.

PHPINFO                           http://localhost/dashboard/phpinfo.php
  The native phpinfo() output with a runtime summary, the list of loaded
  extensions and 58 collapsible sections, with a table of contents and a
  filter.

 4. DESIGN SYSTEM
-------------------------------------------------------------------------------

Everything lives in one stylesheet: dashboard/stylesheets/all.css

Colours, dark theme, with the contrast ratio against the page background:

    --accent     #FB7A24    7.40:1  AAA   actions, active state
    --accent-ink #1A0A00    7.28:1        text on top of the accent
    --cyan       #FFB35C   11.09:1  AAA   data and databases
    --violet     #FF6B3D    6.95:1  AA    code and tooling
    --amber      #FFC15E   12.21:1  AAA   advisory blocks
    --danger     #E5341C    4.53:1  AA    failures

Light theme: the same hues darkened (#A8480B, #8A4A08, #A8380F, #7A4E10,
#A3200D), never below 5.4:1.

The rest of the system: a 4 pixel spacing scale, six corner radii, three
shadow levels, a twelve column grid compatible with the existing markup, and
220 ms transitions on a single easing curve.

 5. ACCESSIBILITY
-------------------------------------------------------------------------------

  - Skip link and <main> landmark on every page.
  - Focus rings always visible, never removed.
  - Interactive areas of at least 44 pixels.
  - aria-current on the active menu entry, aria-expanded on the disclosure
    menus.
  - FAQ accordion and language menu operable from the keyboard, closing with
    Esc.
  - prefers-reduced-motion honoured: animations are cancelled.
  - Information is never carried by colour alone.

Fifteen languages: English, Italian, German, Spanish, French, Brazilian

 8. DOWNLOAD AND INSTALL
-------------------------------------------------------------------------------

FIRST OF ALL: back up your htdocs folder.

    cd /Applications/XAMPP/xamppfiles          # macOS
    sudo cp -R htdocs htdocs-backup

Download with git:

    cd /tmp
    git clone https://github.com/chirurgiadigitale/xampp.git xampp-restyling

Or as an archive, from the project page on GitHub:
"Code" > "Download ZIP", then extract it.

Copy the files into the web root, without touching your own projects:

    sudo cp -R /tmp/xampp-restyling/dashboard   /Applications/XAMPP/xamppfiles/htdocs/
    sudo cp -R /tmp/xampp-restyling/img         /Applications/XAMPP/xamppfiles/htdocs/
    sudo cp    /tmp/xampp-restyling/index.php   /Applications/XAMPP/xamppfiles/htdocs/
    sudo cp    /tmp/xampp-restyling/.htaccess   /Applications/XAMPP/xamppfiles/htdocs/

    # projects index: the folder stays yours, only the index page is added
    sudo mkdir -p /Applications/XAMPP/xamppfiles/htdocs/progetti
    sudo cp /tmp/xampp-restyling/progetti/index.php /Applications/XAMPP/xamppfiles/htdocs/progetti/
    sudo cp /tmp/xampp-restyling/progetti/.htaccess /Applications/XAMPP/xamppfiles/htdocs/progetti/

Fix the permissions (see section 9), then open:

    http://localhost/dashboard/

Nothing needs building: these are pages served as they are.

NOTE: the progetti/ folder of the project is deliberately empty. Whoever
downloads this build starts with no projects and no data in the databases.

 9. PERMISSIONS ON macOS
-------------------------------------------------------------------------------

On macOS the XAMPP files belong to root and Apache runs as "daemon". After
copying the files the permissions must be fixed, or the server answers 403.

    XR=/Applications/XAMPP/xamppfiles/htdocs

    # owner root, group admin: the arrangement XAMPP uses
    sudo chown -R root:admin $XR/dashboard $XR/progetti/index.php

    # readable by everyone, writable only by the owner
    sudo chmod -R a+rX $XR/dashboard
    sudo chmod 644 $XR/progetti/index.php $XR/.htaccess $XR/progetti/.htaccess

    # if you copied the phpMyAdmin theme script
    sudo chmod +x $XR/dashboard/phpmyadmin-theme/install.sh

Check:

    curl -o /dev/null -w "%{http_code}\n" http://localhost/dashboard/

It must answer 200. A 403 almost always means a parent folder is not readable:
check with

    ls -la /Applications/XAMPP/xamppfiles/htdocs

The PHP pages need shell_exec to be allowed in order to read the listening
ports. If it is disabled, the Ports & IPs page says so openly and everything
else keeps working.


-------------------------------------------------------------------------------
 10. WINDOWS AND LINUX
-------------------------------------------------------------------------------

The restyling is written to run on every system XAMPP supports. Paths are not
written into the code: they are derived by walking up from the location of the
files, so the install root is found wherever it is.

    macOS      /Applications/XAMPP/xamppfiles
    Linux      /opt/lampp
    Windows    C:\xampp

Apache configuration files are looked up under etc/ on macOS and Linux, under
apache\conf\ on Windows.

LINUX (Debian, Ubuntu, Fedora...)

    sudo cp -R xampp-restyling/dashboard /opt/lampp/htdocs/
    sudo cp xampp-restyling/index.php /opt/lampp/htdocs/
    sudo cp xampp-restyling/.htaccess /opt/lampp/htdocs/
    sudo chown -R root:root /opt/lampp/htdocs/dashboard
    sudo chmod -R a+rX /opt/lampp/htdocs/dashboard
    sudo /opt/lampp/lampp restartapache

WINDOWS

    Copy the folders into C:\xampp\htdocs\ with File Explorer.
    Permissions need no attention.
    Restart Apache from the XAMPP Control Panel.

    The .htaccess file only works if httpd.conf contains AllowOverride All
    inside the <Directory "C:/xampp/htdocs"> block.

DIFFERENCES WORTH KNOWING

  - The Ports & IPs page uses netstat, available on all three systems, and
    reads both the BSD/macOS and the Windows column layout. Process details
    come from lsof and ps, available on macOS and Linux: on Windows the ports
    are still listed, without the process name.
  - The command to restart Apache is shown already adapted to the system in
    use, on the Ports & IPs page.
  - The light theme, the translations and everything else are identical
    everywhere.

The project was developed and verified on macOS with XAMPP 8.2.4. Windows and
Linux support is written following the conventions of each system but has not
been tested in the field: reports are welcome.

 11. phpMyAdmin THEME
-------------------------------------------------------------------------------

The project also carries a theme that brings the same look inside phpMyAdmin,
in dashboard/phpmyadmin-theme/

The theme does not rewrite phpMyAdmin: it starts from the stock pmahomme theme
and appends the dashboard stylesheet to it, so the application stays
upgradeable.

Install:

    cd /Applications/XAMPP/xamppfiles/htdocs/dashboard/phpmyadmin-theme
    sudo bash install.sh

On Linux:

    sudo bash install.sh /opt/lampp/phpmyadmin

Activate it from the theme selector on the phpMyAdmin home page, or by adding
this line to phpmyadmin/config.inc.php:

    $cfg['ThemeDefault'] = 'xampp-v2';

If a phpMyAdmin update overwrites the themes folder, just run the script again.

PREVIEW BEFORE INSTALLING

    http://localhost/dashboard/phpmyadmin-theme/preview.html

The page shows the real phpMyAdmin components (tabs, result table, SQL editor,
alerts, forms, database tree, console) with the theme stylesheet applied, so
the result can be judged without touching the installation.

WHAT IT COVERS, AND WHAT IT DOES NOT

The theme is an override stylesheet of 102 rules: it redefines colours,
typography, borders and radii for the components met while using phpMyAdmin.
The pmahomme base theme declares more than 2500 selectors: the less travelled
parts of the interface keep their original look, adapted to the new colours
only where the general rules reach.

In practice: the everyday screens (database list, structure, results, SQL,
import and export, messages) follow the dashboard design. Some advanced
configuration pages may still show elements in the original style. That is not
an installation fault: it is the limit of a theme built by overlay instead of
rewriting phpMyAdmin, a choice made so that its updates keep working.

The theme folder is not browsable over the web (it answers 403): it holds
sources, not pages. Use the preview, or read the stylesheet:

    http://localhost/dashboard/phpmyadmin-theme/xampp-v2/css/overrides.css

 12. phpMyAdmin INSIDE THE DASHBOARD
-------------------------------------------------------------------------------

The Database page shows phpMyAdmin inside the dashboard frame, with the
navigation bar and the footer always visible.

phpMyAdmin refuses to be displayed inside a frame, answering with the header
X-Frame-Options: DENY. To allow it from the same host, add this to
phpmyadmin/config.inc.php:

    $cfg['AllowThirdPartyFraming'] = 'sameorigin';

Ready to paste, on macOS:

    sudo sh -c 'echo "\$cfg[\"AllowThirdPartyFraming\"] = \"sameorigin\";" \
      >> /Applications/XAMPP/xamppfiles/phpmyadmin/config.inc.php'

Until you do, the page explains the situation and offers the link to open
phpMyAdmin in a separate tab: nothing breaks.

Note: 'sameorigin' allows embedding only from this same machine.

 13. PRIVACY OF THE LOCAL ENVIRONMENT
-------------------------------------------------------------------------------

This build ships empty: no projects, no databases, no port configuration.

The Ports and Projects pages hold no data: they read the system when opened.
Whoever downloads the project gets the scanner only.

The .gitignore file uses an allow list: everything is excluded and only the
files belonging to the distribution come back in. On top of that,
.githooks/pre-commit refuses a commit carrying project folder names, private IP
addresses, Listen directives, real DocumentRoot paths, database dumps or
credentials.

To enable the check after cloning:

    git config core.hooksPath .githooks

The bundled .htaccess turns off automatic directory listing in the web root,
denies access to .env files, dumps, keys and dotfiles, and blocks any request
to the .git folder. Inside progetti/ the listing stays on, because that is
where it is useful for work.
