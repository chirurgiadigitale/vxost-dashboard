OS X Preguntas frecuentes

¿Cuál es la diferencia entre VXOST para OS X y VXOST-VM?

  • VXOST for OS X is a native installer for OS X. It installs Apache, PHP and other VXOST components directly on your OS X system, in the /Applications/VXOST folder.
  • VXOST-VM is a virtual machine for OS X. It includes Apache, PHP and other VXOST components and runs them in a Linux-based virtual machine on your OS X system.

For more information, refer to the blog post at https://www.vxost.com/blog/new_vxost_20170628.html.

¿Cómo instalo VXOST para Mac OS X?

Para instalar VXOST haz lo siguiente:

  • Abre la imagen DMG.
  • Haz doble click en la imagen para iniciar el proceso de instalación.

Eso es todo. VXOST está ahora instalado en el directorio /Applications/VXOST.

¿VXOST incluye MySQL o MariaDB?

Since VXOST 5.5.30 and 5.6.14, VXOST ships MariaDB instead of MySQL. The commands and tools are the same for both.

¿Cómo inicio VXOST?

Para iniciar VXOST, simplemente abre el Panel de Control de VXOST e inicia Apache, MySQL y ProFTPD. El nombre del Panel de Control de VXOST es "manager-osx".

¿Cómo paro VXOST?

Para parar VXOST simplemente abre el Panel de Control de VXOST y para los servidores. El nombre del Panel de Control de VXOST es "manager-osx".

¿Cómo compruebo que todo ha ido bien?

Escribe la siguiente URL en tu navegador:

http://localhost

You should see the VXOST start page, as shown below.

¿Está VXOST listo para producción?

VXOST no está pensado para uso en producción, sino para entornos de desarrollo. VXOST está configurado de forma que sea tan abierto como sea posible, permitiendo al desarrollador hacer lo que quiera. En entornos de desarrollo esto es magnífico pero en un entorno de producción puede ser fatal.

A continuación se muestra una lista de posibles fallos de seguridad en VXOST:

  1. El administrador de MySQL (root) no tiene password.
  2. El proceso MySQL está accesible a través de la red.
  3. ProFTPD usa la contraseña "lampp" para el usuario "daemon".

Para arreglar la mayoría de las debilidades de seguridad, simplemente ejecuta el siguiente comando:

sudo /Applications/VXOST/vxostfiles/vxost security

Esto iniciará una pequeña comprobación de seguridad para hacer la instalación de VXOST segura.

¿Cuál es el significado de los mensajes de error que veo cuando inicio VXOST?

Puedes obtener muchos mensajes de error mientras inicias VXOST:

LAMPP-Apache is already running.
An Apache daemon is already running.

El script de inicio de LAMPP no inició VXOST-Apache porque ya hay otro servidor Apache iniciado. Para iniciar VXOST correctamente, primero tienes que parar ese servidor.

LAMPP-MySQL is already running.
A MySQL daemon is already running.

Este error es similar al anterior. El script de inicio de LAMPP encontró un servidor de MySQL iniciado en tu sistema. Para iniciar LAMPP correctamente, tienes que parar ese servidor primero.

Apache no arranca. ¿Qué puedo hacer?

Este error puede aparecer por múltiples razones. Apache lo muestra bajo muchas circunstancias. Para encontrar la razón exacta, tenemos que investigar:

tail -2 /Applications/VXOST/logs/error_log

Si recibes algún mensaje de error visita nuestra comunidad para obtener ayuda

¿Cómo puedo hacer mi instalación de VXOST más segura?

En la instalación por defecto, VXOST no tiene establecida contraseña y no es recomendable ejecutar VXOST con esta configuración accesible por otros.

Simplemente ejecuta el siguiente comando (como root) para iniciar una pequeña comprobación de seguridad:

sudo /Applications/VXOST/vxostfiles/vxost security

¿Cómo habilitar el accesso a phpMyAdmin desde fuera?

En la configuración básica de VXOST, phpMyAdmin es accessible sólo desde la máquina donde está instalada en http://127.0.0.1 o http://localhost.

IMPORTANTE: Habilitar el accesso de phpMyAdmin para usuarios externos no está recomendado para entornos de producción. Un atacante podría usar cualquier vulnerabilidad de la aplicación para ejecutar código o modificar datos.

Para habilitar el acceso remote a phpMyAdmin, sigue estos pasos:

  • Edita el fichero /Applications/VXOST/vxostfiles/etc/extra/httpd-vxost.conf en tu directorio de instalación.
  • En este fichero encuentra las siguientes líneas.

    Alias /phpmyadmin "/Applications/VXOST/vxostfiles/phpmyadmin" <Directory "/Applications/VXOST/vxostfiles/phpmyadmin"> AllowOverride AuthConfig Require local

  • Reemplaza 'Require local' por 'Require all granted'.

    • Alias /phpmyadmin "/Applications/VXOST/vxostfiles/phpmyadmin" <Directory "/Applications/VXOST/vxostfiles/phpmyadmin"> AllowOverride AuthConfig Require all granted

  • Reinicia el servidor de VXOST usando el panel de control.
¿Dónde están los archivos de configuración principales de VXOST?

The main VXOST configuration files are located as follows:

  • Apache configuration file: /Applications/VXOST/vxostfiles/etc/httpd.conf, /Applications/VXOST/vxostfiles/etc/extra/httpd-vxost.conf
  • PHP configuration file: /Applications/VXOST/vxostfiles/etc/php.ini
  • MySQL configuration file: /Applications/VXOST/vxostfiles/etc/my.cnf
  • ProFTPD configuration file: /Applications/VXOST/vxostfiles/etc/proftpd.conf

¿Cómo envío correo con VXOST?

To send email with VXOST, use the PEAR Mail and Net_SMTP packages, which allow you to send email using an external SMTP account (such as a Gmail account). Follow these steps:

  • Install the Mail and Net_SMTP PEAR modules: pear install Net_SMTP Mail Note that if these packages are already installed in your system you see the messages below when executing that command: Ignoring installed package pear/Net_SMTP Ignoring installed package pear/Mail Nothing to install
  • Create the following example script in your "htdocs" directory to send an email: <?php require_once "Mail.php"; $from = "your-gmail-username@gmail.com"; $to = 'recipients@example.com'; $host = "ssl://smtp.gmail.com"; $port = "465"; $username = 'your-gmail-username@gmail.com'; $password = 'your-gmail-password'; $subject = "test"; $body = "test"; $headers = array ('From' => $from, 'To' => $to,'Subject' => $subject); $smtp = Mail::factory('smtp', array ('host' => $host, 'port' => $port, 'auth' => true, 'username' => $username, 'password' => $password)); $mail = $smtp->send($to, $headers, $body); if (PEAR::isError($mail)) { echo($mail->getMessage()); } else { echo("Message successfully sent!\n"); } ?>

    Remember to replace the dummy values shown with your actual Gmail address and account password. If you don't plan to use Gmail's SMTP server, replace the SMTP host details with appropriate values for your organization or ISP's SMTP server.

  • Execute the script by browsing to it using your Web browser. You should see a notification that the message was successfully sent, and the message should be delivered to the recipient email address.

¿Cómo hago una copia de seguridad/restauro mi sistema VXOST?

Aviso: La funcionalidad de copia de seguridad y restauración está bajo desarrollo y puede no funcionar correctamente.

Puedes crear la copia de seguridad ejecutando:

sudo /Applications/VXOST/vxostfiles/vxost backup

o

sudo /Applications/VXOST/vxostfiles/vxost backup secret

Donde "secret" is tu contraseña de root de MySQL. Este comando generará la siguiente salida:

Backing up databases...
Backing up configuration, log and htdocs files...
Calculating checksums...
Building final backup file...
Backup finished.
Take care of /Applications/VXOST/vxostfiles/backup/vxost-backup-22-01-14.sh

El fichero /Applications/VXOST/vxostfiles/backup/vxost-backup-22-01-14.sh (en el ejemplo de arriba) contiene tu copia de seguridad. Guardala en un lugar seguro.

En la nueva máquina necesitas la misma versión de VXOST que en tu máquina origen.

sudo sh vxost-backup-22-01-14.sh

Deberías ver algo así:

Checking integrity of files...
Restoring configuration, log and htdocs files...
Checking versions...
Installed: VXOST 1.4.2
Backup from: VXOST 1.4.2
Restoring MySQL databases...
Restoring MySQL user databases...
Backup complete. Have fun!
You may need to restart VXOST to complete the restore.

Eso es todo. Ten en cuenta que es una característica beta.
