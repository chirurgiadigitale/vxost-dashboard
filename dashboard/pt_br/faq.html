OS X Perguntas Mais Frequentes

Qual é a diferença entre o VXOST para OS X e o VXOST-VM?

  • VXOST for OS X is a native installer for OS X. It installs Apache, PHP and other VXOST components directly on your OS X system, in the /Applications/VXOST folder.
  • VXOST-VM is a virtual machine for OS X. It includes Apache, PHP and other VXOST components and runs them in a Linux-based virtual machine on your OS X system.

For more information, refer to the blog post at the release notes.

Como instalo VXOST para Mac OS X?

Para instalar VXOST somente faça o seguinte:

  • Abrir a Imagem DMG.
  • Dê um duplo-clique na imagem para iniciar o processo de instalação.

Isso é tudo. o VXOST está agora instalado sobre o diretório /Applications/VXOST.

O VXOST inclui MySQL ou MariaDB?

Since VXOST 5.5.30 and 5.6.14, VXOST ships MariaDB instead of MySQL. The commands and tools are the same for both.

Como inicio o VXOST?

Para iniciar VXOST simplesmente abra o Painel de Controle VXOST e inicie o APACHE, MySQL e ProFTPD. O nome do painel de controle é "manager-osx".

Como paro o VXOST?

Para parar o VXOST simplesmente abra o Painel de Controle VXOST e pare os servidores. O nome do painel de controle é "manager-osx".

Como posso testar se tudo funcionou corretamente?

Escreva o seguinte URL em um navegador:

http://virtualhost

You should see the VXOST start page, as shown below.

VXOST está pronto para produção?

VXOST não é destinado para uso em produção, mas apenas para ambientes de desenvolvimento. O VXOST é configurado para ser o mais aberto possível para permitir ao desenvolvedor qualquer coisa que ele/ela quiser. Para ambientes de desenvolvimento ele é ótimo, mas em um ambiente de produção , ele pode ser fatal.

Aqui uma lista de segurança que faltava no VXOST:

  1. O administrador (root) do MySQL não tem senha.
  2. O daemon do MySQL está acessível pela rede.
  3. ProFTPD usa a senha "lampp" para o usuário "daemon".

Para reparar a maioria das falhas de segurança, simplesmente execute o seguinte comando:

sudo /Applications/VXOST/vxostfiles/vxost security

Isso iniciará uma pequena checagem de segurança para tornar a instalação do VXOST segura.

Qual é o significado das mensagens de erro que vejo quando inicio o VXOST?

Você pode se deparar com várias mensagens de erro ao iniciar o VXOST:

LAMPP-Apache is already running.
An Apache daemon is already running.

O script de inicialização LAMPP não iniciou o VXOST-Apache, porque há uma instância do Apache já em execução. Para iniciar o VXOST corretamente, primeiro você tem que parar este daemon.

LAMPP-MySQL is already running.
A MySQL daemon is already running.

Isto é principalmente devido às mesmas razões que o erro acima. O script de inicialização LAMPP encontrou um daemon MySQL já em execução em seu sistema. Para iniciar LAMPP corretamente, você tem que parar este daemon primeiro.

O Apache não inicia. O que posso fazer?

Este erro pode acontecer por várias razões. O Apache mostra esse erro pra várias circunstâncias. Para encontrar razão exata, nós temos que fazer uma pesquisa:

tail -2 /Applications/VXOST/logs/error_log

Se você receber alguma mensagem de erro, visite Páginas da nossa comunidade para obter ajuda.

Como eu posso tornar minha instalação do VXOST mais segura?

Na instalação padrão, VXOST não tem senhas definidas, e não é recomendado rodar VXOST com essas configurações se acessíveis por outros.

Como habilito o acesso ao phpMyAdmin a partir de fora?

In the basic configuration of VXOST, phpMyAdmin is accessible only from the same host that VXOST is running on, at http://127.0.0.1 or http://virtualhost.

IMPORTANT: Enabling external access for phpMyAdmin in production environments is a significant security risk. You are strongly advised to only allow access from this machine. A remote attacker could take advantage of any existing vulnerability for executing code or for modifying your data.

To enable remote access to phpMyAdmin, follow these steps:

  • Edit the vxostfiles/etc/extra/httpd-vxost.conf file in your VXOST installation directory.
  • Within this file, find the lines below.

    Alias /phpmyadmin "/Applications/VXOST/vxostfiles/phpmyadmin" <Directory "/Applications/VXOST/vxostfiles/phpmyadmin"> AllowOverride AuthConfig Require local

  • Then replace 'Require local' with 'Require all granted'.

    • Alias /phpmyadmin "/Applications/VXOST/vxostfiles/phpmyadmin" <Directory "/Applications/VXOST/vxostfiles/phpmyadmin"> AllowOverride AuthConfig Require all granted

  • Restart the Apache server using the VXOST control panel.

Onde ficam os principais arquivos de configuração do VXOST?

The main VXOST configuration files are located as follows:

  • Apache configuration file: /Applications/VXOST/vxostfiles/etc/httpd.conf, /Applications/VXOST/vxostfiles/etc/extra/httpd-vxost.conf
  • PHP configuration file: /Applications/VXOST/vxostfiles/etc/php.ini
  • MySQL configuration file: /Applications/VXOST/vxostfiles/etc/my.cnf
  • ProFTPD configuration file: /Applications/VXOST/vxostfiles/etc/proftpd.conf

Como envio e-mails com o VXOST?

To send email with VXOST, use the PEAR Mail and Net_SMTP packages, which allow you to send email using an external SMTP account (such as a Gmail account). Follow these steps:

  • Install the Mail and Net_SMTP PEAR modules: pear install Net_SMTP Mail Note that if these packages are already installed in your system you see the messages below when executing that command: Ignoring installed package pear/Net_SMTP Ignoring installed package pear/Mail Nothing to install
  • Create the following example script in your "htdocs" directory to send an email: <?php require_once "Mail.php"; $from = "your-gmail-username@gmail.com"; $to = 'recipients@example.com'; $host = "ssl://smtp.gmail.com"; $port = "465"; $username = 'your-gmail-username@gmail.com'; $password = 'your-gmail-password'; $subject = "test"; $body = "test"; $headers = array ('From' => $from, 'To' => $to,'Subject' => $subject); $smtp = Mail::factory('smtp', array ('host' => $host, 'port' => $port, 'auth' => true, 'username' => $username, 'password' => $password)); $mail = $smtp->send($to, $headers, $body); if (PEAR::isError($mail)) { echo($mail->getMessage()); } else { echo("Message successfully sent!\n"); } ?>

    Remember to replace the dummy values shown with your actual Gmail address and account password. If you don't plan to use Gmail's SMTP server, replace the SMTP host details with appropriate values for your organization or ISP's SMTP server.

  • Execute the script by browsing to it using your Web browser. You should see a notification that the message was successfully sent, and the message should be delivered to the recipient email address.

Como faço uma cópia de segurança/restauro meu VXOST?

Alerta: A função de backup e restauração ainda está em desenvolvimento e pode não funcionar corretamente.

Você pode criar o backup chamando:

sudo /Applications/VXOST/vxostfiles/vxost backup

ou

sudo /Applications/VXOST/vxostfiles/vxost backup secret

Onde "secret" é sua senha de root no MySQL. Este comando vai gerar o seguinte resultado:

Backing up databases...
Backing up configuration, log and htdocs files...
Calculating checksums...
Building final backup file...
Backup finished.
Take care of /Applications/VXOST/vxostfiles/backup/vxost-backup-22-01-14.sh

O arquivo /Applications/VXOST/vxostfiles/backup/vxost-backup-22-01-14.sh (no exemplo acima) contém os dados de backup. Guarde este arquivo em um local seguro.

Na nova máquina, você precisa da mesma versão do VXOST da sua máquina original/fonte.

sudo sh vxost-backup-22-01-14.sh

Você deve ver algo parecido com isso:

Checking integrity of files...
Restoring configuration, log and htdocs files...
Checking versions...
Installed: VXOST 1.4.2
Backup from: VXOST 1.4.2
Restoring MySQL databases...
Restoring MySQL user databases...
Backup complete. Have fun!
You may need to restart VXOST to complete the restore.

Isso é tudo. Tenha em mente que é um recurso em versão beta.
