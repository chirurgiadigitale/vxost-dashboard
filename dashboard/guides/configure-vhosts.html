Configure Virtual Hosts

A virtual host lets one Apache serve several projects at once, each on its own address. In VXOST every project answers on its own port — http://virtualhost:4000, http://virtualhost:4001 — rather than on a made-up domain name.

The port is what keeps projects apart, and it needs nothing outside Apache. A custom name such as myproject.virtualhost would also have to be added to /etc/hosts, on every machine that has to reach it.

The short way: let the app do it

Open VXOST and press New project. Give it a name, pick a port, and optionally the address of a Git repository and the PHP version you want. VXOST creates the folder, writes the virtual host, checks the configuration and restarts Apache.

The app validates the configuration before restarting Apache, and puts the previous file back if the check fails. Doing it by hand, a typo stops the web server until you find it.

The long way: by hand

Everything below is what the wizard writes for you. It is worth reading once, because it is also what you will edit the day a project needs something unusual.

  1. Put the project in its own folder under the web root:

    /Applications/VXOST/vxostfiles/www/projects/my-site

  2. Open etc/httpd.conf and check that the virtual hosts file is included. The line is there by default; if it starts with a hash, remove it:

    Include etc/extra/httpd-vhosts.conf

  3. In the same file, tell Apache to listen on the port you picked. Next to the other Listen lines, add:

    Listen 127.0.0.1:4000

    The address matters. Listen 127.0.0.1:4000 answers this Mac only; Listen 4000 answers every machine on the same network, which means anyone on your wi-fi can read the site you are working on. VXOST ships closed and asks you in the setup wizard.

  4. Open etc/extra/httpd-vhosts.conf and add one block per project:

    <VirtualHost *:4000>
    DocumentRoot "/Applications/VXOST/vxostfiles/www/projects/my-site"
    ServerName virtualhost
    <Directory "/Applications/VXOST/vxostfiles/www/projects/my-site">
        Options Indexes FollowSymLinks
        AllowOverride All
        Require all granted
    </Directory>
    ErrorLog "logs/my-site-error_log"
    CustomLog "logs/my-site-access_log" common
</VirtualHost>

    AllowOverride All is what makes .htaccess work, so WordPress permalinks and Laravel routes behave as they do on a real server. A separate log per project means an error tells you straight away whose it is.

  5. Check the configuration before restarting. This is the step that separates a typo from a web server that will not start:

    /Applications/VXOST/vxostfiles/bin/httpd -t

    It answers Syntax OK, or it names the file and the line. Only then restart Apache from the app or from the Terminal:

    sudo /Applications/VXOST/vxostfiles/vxost restartapache

  6. Open http://virtualhost:4000. The project list in the app shows every virtual host with the port it answers on, so you can check from there too.

If you really want a name instead of a port

Use ServerName my-site.virtualhost in the block above, then map the name to this machine by adding a line to /etc/hosts:

127.0.0.1    my-site.virtualhost
That line lives on this Mac only. A phone or another computer will not resolve the name until the same mapping is added there as well, which is why ports are the simpler answer for local development.

What VXOST is

A free Apache distribution that installs a complete web server on your computer: Apache, the MariaDB database, PHP and Perl, ready to develop and test locally without touching a production server.
